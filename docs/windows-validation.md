## 格式与页面身份

生成素材回归覆盖：

- ZIP/CBZ 直接读取，嵌套目录、UTF-8 和常见 GB18030 中文路径、1/2/10 自然排序与隐藏元数据过滤。
- 文件夹或 ZIP 插入排序更早的图片后，已有页面身份与阅读定位不变；损坏图片保留位置；非法路径、损坏包和无图片包被拒绝。
- 单张图片、递归图片文件夹与 TIFF 多帧的真实渲染；TIFF 第二帧、尺寸相关解码缓存、冻结位图与大图资源上限。
- PDF 页数、尺寸、栅格内容、密码错误与正确密码、取消渲染、关闭后释放源文件，以及多个文档的独立生命周期。
- 无 DRM 的 MOBI 6 图片漫画：未压缩与 PalmDOC、封面、正文图片、重复引用和缺失位置；不支持或损坏格式明确报错。

PDFium 保留自 0.6.0 的实现选择：此前 Windows 系统 PDF 路径在远端检查结束时出现原生退出异常，定位后改用随程序分发的 PDFium，串行化原生调用并显式释放页面、位图与文档。该历史不表示当前仍使用系统 PDF 或网页渲染。

## 原生 EPUB 与页面朝向

EPUB 现在面向图片漫画，遵循 spine 顺序，在原生画布显示 DOM 图片、SVG 图片引用和可提取的 CSS 背景图。重复引用、同一页多张图片和缺失资源位置保留；纯文字内容与无法提取图片的页面显示原生提示，不执行 HTML/CSS 文字排版或脚本。

回归检查覆盖匹配当前元素及祖先的旋转规则、层叠与明确的 0°、SVG 与容器旋转；无关样式不能旋转整本书。朝向优先级为：

1. 用户的手动修正。
2. 当前页明确的 EPUB 旋转标记，包含 0°。
3. 仅在没有标记时使用已启用的自动识别。

明确标记不受 OCR 推断覆盖，关闭自动识别仍遵循该标记。CJK 分析参考 macOS 字形方法，区别文字排列方向与字符自身方向；生成素材检查覆盖横排、竖排、多角度、第二种字体，以及对称重复装饰和无文字图案的拒绝。Windows OCR 语言不可用时会明确记录跳过；跳过不算相应字形检查通过。

真实 WPF 检查使用原生 EPUB 页面，验证修正控件可用、旋转确实改变画布内容、配对/交换/解除配对、保存修正、阅读方向变化时确认双图的物理左右不变，以及窗口一次关闭。

## 整本后台分析与缓存

新增的核心与真实窗口检查覆盖以下链路：

- 打开书籍后按来源顺序分析整本，不要求用户逐页翻阅。分析图片最长边为 1100 像素；仅保留必要的当前和前一张分析图，不把全书解码图放入内存。
- 已完成的朝向与相邻接缝结果写入本地 `analysis/` 缓存。缓存身份包含源修订、页面定位、明确的出版物朝向、算法版本及 OCR 语言环境；不匹配的旧缓存不能复用。
- 中途取消或关闭时保留已完成检查点；再打开从未完成部分继续。失败页面不伪装成已完成，后续页面继续分析，未完成项可以重试。
- 完整缓存再次打开时不重新进行分析渲染；重新分析清理的是自动结果，不修改进度、书签或手动修正。
- 后台解码与文档关闭串行协调，OCR 不占用前台文档 I/O 锁；前台翻页优先。切换书籍与一次关闭请求均取消并等待旧任务，释放旧书句柄。
- 用户停留在第一页时，生成书的末页朝向和远处真实连续图接缝仍会被发现；导航到已分析结果时直接使用它们，后台工作不改变用户保存的阅读页码。
- 当前显示内容不会因后台结果到达而突然旋转或合并；需要更新当前画面时显示“应用识别”，或在后续导航时使用新结果。

## 普通双页与智能跨页证据

普通“双页”模式按阅读方向并排显示相邻页；它与通过接缝证据合成的智能跨页是不同的布局结果。生成回归检查普通双页不会冒充智能接缝、候选左右竞争、单页模式下完整跨页仍可成立、手工修正优先，以及每个来源页只消费一次。手工确认的左右位置独立于之后的阅读方向变化。

实际只读审计抽样 **4 册、888 页、884 条相邻接缝**，使用与运行时一致的 **1100 像素**分析输入，解码失败为 0。实际页面先经渲染，再进行朝向和接缝分析；候选经过邻居竞争、朝向约束与真实 `LayoutEngine` 分组。

- 使用当前接缝建议策略，最终得到 **17 组**可显示的智能跨页；采用较严格策略时为 **2 组**。
- 17 组集中在其中一册；其余三册最终为 0 组，没有为了数量强行配对。
- 这 17 组不是单纯按文件名或相邻页号列出的候选，而是实际分析后通过最终布局规则的结果。
- 本次未对这 17 组逐一执行 `MainWindow` 合成后的像素比对，也没有人工逐组确认出版物原意。因此不能将“17 组通过策略”写成识别准确率、全部真实跨页的召回率，或全部最终画布都经过人工验收。

原始漫画及其页面图像没有修改，也不作为公开测试素材提交。公开回归依靠生成的连续画面、噪声接缝、偏移/缩放、空白、重复图和对称图案验证接受与拒绝规则。

## 系列书库与记录保护

真实 WPF 书库检查覆盖空态、文件/目录导入、封面位图实际加载、默认系列总览、点击系列进入分卷、自然卷序、网格/列表切换、分页、搜索、收藏、状态筛选和元数据编辑。

来源目录增量刷新、缺失与恢复、停止扫描、重新打开书库和从封面打开阅读器均有独立检查。进度与书库元数据分开合并，防止另一窗口的旧阅读快照覆盖手动书名、系列、标签、收藏与阅读状态。原子保存、备份恢复、跨实例合并和移除记录保留原书继续覆盖。

系列沿用 macOS 的父目录分组。卷序按 macOS 的 `卷` / `vol` / `volume` 数字规则，从原文件名提取，再以显示标题自然排序和路径稳定排序；改显示书名不会改变该来源的卷号。纯字符串回归包含小数卷、无卷号回退、与年份等无关数字的区分、手动改名及同名排序，不读取用户漫画。

## 验证边界

- 本地通过不能替代远端 CI；远端结果应以该提交的 Windows 工作流实际记录为准。
- EPUB 原生图片提取不等价于完整电子书排版；纯文字、复杂 CSS 排版和脚本不执行。
- CJK 与其他 OCR 结果受到语言、字体、画质、文字数量及页面构图影响；没有针对全部真实漫画给出准确率承诺。
- 未穷尽所有 PDF 加密方案、图像编码、Windows 显示缩放和 OCR 语言组合。
- 本文件只描述 Windows 实际代码与所列检查，不代表 macOS、Android 同时完成了构建或运行验证。
